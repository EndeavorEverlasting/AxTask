## Approach

1. **Define the real target.** You are not building “a prettier spreadsheet.” You are building a **task capture and automation system** that happens to sync with Google Sheets for now.
2. **Split the problem into layers.** If you do not separate sheet logic, Apps Script logic, web UI, and debugging tools, the whole thing turns into swamp water.
3. **Design for your actual behavior.** You said it plainly: most of the time you only want to enter **Activity** and **Notes**. Good. That should become the main workflow, not an afterthought.
4. **Treat the spreadsheet as a compatibility layer.** It is useful, but it should not be the throne. The web app should be the throne.
5. **Build a debug lab first.** A dedicated repo for testing formulas, Apps Script, sync behavior, TaskID assignment, and UI assumptions is exactly the right move.

# What the web version should actually do

## Core principle

The default task entry flow should be **minimal-entry-first**.

### Fast entry mode

You type only:

* **Activity**
* **Notes**

Everything else is inferred or defaulted where possible.

### Assisted mode

Optional fields expand only when needed:

* priority override
* urgency
* impact
* effort
* domain
* tags
* prerequisite
* sub-priority
* time window
* subtype

### Review mode

A polished dashboard shows:

* today’s tasks
* incomplete tasks
* highest priority inferred tasks
* grouped tasks by date/domain/tag
* archived items
* debug warnings

### Debug mode

A special admin/debug panel shows:

* rows missing TaskID
* duplicate TaskIDs
* rows with invalid dates
* formulas not present where expected
* checkbox validation missing
* score/priority mismatches
* sync failures
* Apps Script execution logs surfaced in a sane UI

That last one matters. That is where the pain gets killed.

# What should be automated

You already gave the key clue:

> I only populate activity and notes most of the time.

Good. Then the system should automate the rest where sensible.

## Auto-populate candidates

* **Date** from today if missing
* **TaskID** on first meaningful edit
* **Priority** from Score unless manually overridden
* **Score** from Urgency/Impact/Effort when present
* **Domain** inferred from keywords
* **Tags** inferred from Notes and Activity
* **Subtypes** inferred from pattern rules
* **Result checkbox** default false
* **Time grouping** inferred from entry time
* **Auto Override** applied from rule engine for special cases

## Rules engine examples

If Notes contains:

* “call”, “text”, “email” → communication domain
* “deploy”, “tracker”, “sheet”, “script” → ops/dev domain
* “buy”, “pay”, “invoice” → finance/admin domain
* “gym”, “walk”, “meal prep” → personal health domain

That sort of thing.

Not magic. Controlled inference.
